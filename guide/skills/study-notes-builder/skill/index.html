Study Notes Builder

Turn whatever the user hands you (PDFs, PPTX, images, a syllabus, a topic list) into one cohesive PDF of detailed, simple-to-read, visual study notes: every topic runs intuition → mathematics → boxed algorithm → verified worked examples → common pitfalls → practice, in syllabus order, with a consistent visual language and exam-focused end-matter.

Built with Typst and a fixed, proven package stack. Source extraction uses lit (liteparse) when it is installed, else the Read tool.

When this applies

Trigger phrases: “make notes / cheatsheet / detailed notes / revision notes / study guide for ”, “turn these PPTs into notes”, “notes from this syllabus”, “cover these topics as notes”. The user usually attaches PDFs/PPTs or names topics.

Not this skill: writing a single short explainer, editing an existing prose doc, or answering one conceptual question.

Hard rules

  1. Grill before building. Never start writing sections until the user has answered the intake questions and approved a plan. Use the round-based question format in step 3.
  2. Verify every number. Every worked numerical example is recomputed from scratch in a throwaway script (scratchpad/verify/*.py) and the notes show the verified value. Where the verified value differs from the source, state it and add a margin note. The note never names the source. Do this before writing the prose for that section.
  3. Zero-warning compile gate. typst compile main.typ out.pdf must exit 0 with no warnings (Typst warns on overflow boxes and unresolved refs — treat any as a defect).
  4. Augment, don’t transcribe. Fill gaps the source assumes (foundational definitions, adjacent topics it leads into) from your knowledge base — but stay inside the scope the user set in the grill.
  5. Read references/typst-cookbook.md before writing any .typ. It carries the version notes, import/setup lines, the package catalog and the Typst syntax traps that will otherwise cost you several failed compiles.
  6. Search for packages before drawing. Run the package scout (step 2); do not default to the baseline stack when a domain package exists.
  7. Every internal self-reference is a live hyperlink, both ways. Whenever the notes point at another part of themselves — “see Appendix C”, “the recall formula above”, “as in the perceptron worked example”, “Part II covers this” — that phrase must be a clickable link to the target, and the target must carry a subtle backlink to the referring spot. Use xref / backlink from template.typ: label the target heading/block <app-c>, write the mention as #xref(<app-c>)[Appendix C] and give the call site its own label <q-bpn-appc>, then place #backlink(<q-bpn-appc>) at the target. A target referenced from N spots gets N stacked #backlink(...) markers. This applies to the practice-answer-key ↔ practice-question link, the pitfall-index ↔ body-callout link, and formula-sheet ↔ first-derivation link especially.
  8. Notes stand alone. The reader must never need the source to use the notes. Prose never refers to the source: no “the deck”, “the slide”, “the lecture”, “the PDF”, “the source”, and no slide or page numbers. The only source mention allowed is the light sref tag (see Source tag in the writing rules) and the visible sourcecheck callout (unit/lecture name only). No slide numbers unless the user explicitly asks for slide-level provenance. Source pages live in coverage.md.
  9. The config is the contract. notes-config.md (recipe + verbatim remarks) decides what goes in; check every section and the final build against it.

Workflow

0. Wizard — build your own notes

The user assembles a recipe; you record it in notes-config.md (references/notes-config.md is the template). Two rounds of AskUserQuestion (max 4 questions each, recommended answer first), then one free-text prompt. Skip fields the user already stated.

Round A (shape):

  1. Note type: Quick revision (dense, formulas + pitfalls, no derivations), Detailed study (default), Exam notes (detailed + study order, exam-priority table, quick checks), Handbook (lookup: formula sheet, comparison tables, index).
  2. Engine: Typst (default; math-heavy), Typst + embedded visuals (hero/3D/plot figures made in HTML/Three.js/matplotlib, embedded as PNG), HTML to PDF (references/html-kit, scripts/html-to-pdf.sh; visual subjects). Recommend by subject.
  3. Visual level: Plain, Balanced (default: a real figure per topic plus chapter heroes), Rich (heavy 3D/illustrated even where content is not naturally visual; honest analogies). See references/rich-visuals.md.
  4. Density and tone: concise / normal / thorough, and terse / friendly / formal.

Round B (ingredients), multi-select: 5. Per-topic blocks (pick what to include): intuition, derivations, worked examples (ask count), practice (ask count), pitfalls, exam tips, mnemonics, quick checks, source checks, comparison tables. 6. Front/end matter: study order + exam priority, formula sheet, pitfall index, glossary, problem-attack guide, answer key, source-check register. 7. Look: chapter covers (none / banner / banner+hero), colour (one accent / per-chapter / custom). 8. Scope: what to emphasise or skip, notation target.

Then ask in plain chat: “Additional remarks? Anything you want done or avoided, in your own words.” Record it verbatim under Additional remarks. Repeat this prompt at the end of every grill round.

Remarks are binding. They override defaults and recipe fields. If a remark conflicts with a hard rule or gate, say so, ask once, record the decision under Conflicts noted; hard rules stand unless the user waives them explicitly. Show the filled notes-config.md, get a yes, and re-read it before each section. Pass it verbatim to every writer subagent. Step 7 checks the build against it.

Mode defaults when a field is left unset: Quick = no derivations, 1 example per topic, no practice, no covers; Exam = study order + exam-priority table + a check per topic; Detailed = as specified below; Handbook = formula sheet, comparison matrices and index first-class.

1. Intake — gather and extract sources

  • List what the user gave: file paths, topic list, syllabus text.
  • If lit is installed (command -v lit), batch-extract every document to text: bash <skill>/scripts/extract.sh "<src_dir>" "<out_dir>" (wraps lit parse; falls back to per-file). Otherwise Read each file (PDFs via the pages arg).
  • Image-heavy sources: slides that are pictures or scans have little or no text layer. extract.sh flags pages with under 15 words (<name>.imgpages.txt) and OCRs them with tesseract (<name>.ocr.txt). For PPTX/images and for flagged pages, also render the page (pdftoppm -r 150) and Read the PNG: OCR misses diagrams, tables and formulas. Digest agents must report OCR quality per source and treat flagged pages as content to cover, not skip. Tell the user which sources were OCR’d.
  • If the user gave only topics / a syllabus with no documents, note that the build is knowledge-base-driven and the digest step is skipped.

2. Digest — understand the material (subagent)

Dispatch one Explore (or general-purpose) subagent over the extracted text. Ask it to report, per source:

  • topic/title, ordered concept list
  • every formula (transcribed from the OCR as best it can)
  • every worked numerical example (inputs given, method)
  • diagrams/architectures described
  • OCR quality (clean / messy / garbled), and which pages needed OCR or a visual read

Before dispatching, tell the user it is working and give an honest ETA (roughly 1 min per 10 source files or 100 pages; say “grab a coffee” if over ~3 min). Ask nothing more until the report is back.

…then a synthesis: the logical teaching order across all sources, the topic clusters, and which standard syllabus topics are absent (so you can propose augmentation). Keep the subagent read-only.

Alongside it, launch these read-only subagents in the same message, each returning a short report with an explicit “nothing found” where applicable:

  • Package scout: given the subject and the list of diagram-worthy concepts (e.g. Bloch sphere, MPI message flow, SDLC/Gantt, DFA, UML, circuits), search the Typst Universe index (cookbook “Package catalog”) and typst.app/universe for packages that draw them. Return: package, latest version, one-line API sketch, and a minimal snippet it has compiled in a scratch file. Also report anything better than the baseline for tables, math annotation, plots (lilaq), margin notes.
  • Figure scout (if sources are PDFs/slides): render candidate figure pages to PNG and report the crop box for each usable figure.

3. Grill — resolve the design tree

Work in rounds. Each round asks every question whose prerequisites are settled; number them and give a recommended answer; then wait. Format:

❓ **Q1 — <title>**: <body, with options>

➡️ <your recommended answer>

Cover at least (skip what notes-config.md already settles):

  • Scope / augmentation depth — source topics only + light augmentation, or source topics + the adjacent foundations they assume, or the full standard syllabus. (Recommend the middle.)
  • Purpose & notation — which exam/board/textbook to align notation to (infer from the decks if possible, e.g. a named textbook); cheatsheet vs teaching notes.
  • Worked-example treatment — recompute all source problems + N extra solved per topic + M practice questions with an answer-key appendix. (Recommend recompute-all, 2 extra, 3–5 practice.)
  • Visual investment — how far to go on diagrams, and which concepts get custom diagrams (propose packages from the scout), e.g. architecture node-graphs, function plots, geometry sketches, signal-flow.
  • Document skeleton — the ordered part/chapter list; confirm it.
  • Deliverable form — .typ sources + compiled PDF + README (default yes).
  • Source screenshots / redraws — crop source figures where clearer; redraw (Typst diagram or rich-visuals) where the original is blurry, cluttered or a 3D plot that deserves a proper render (recommend: screenshot if sharp, else redraw).
  • Colour / print — colour-first screen, print-safe (callouts distinguished by icon and label, diagrams legible in greyscale).

Recompute the frontier after each round. Stop when nothing is left unasked, then present a short written plan (Goal / Constraints / Structure / Deliverables / Verification) and get an explicit yes.

4. Scaffold the project

HTML track: copy references/html-kit/ (notes.css, skeleton.html) instead of the Typst files, write one .html per Part, build with bash <skill>/scripts/html-to-pdf.sh main.html out.pdf. Hard rules, verify scripts, coverage and structure gates apply unchanged (structure-check reads .typ only: review HTML pages by rendering to PNG). Typst layout below.

Create in the user’s chosen directory:

<proj>/
├── main.typ            # config + title + "how to use" + TOC + part dividers + includes
├── template.typ        # copy references/template.typ  (styles, callouts, theorem envs, worked/algo/practice)
├── diagrams.typ        # copy references/diagrams.typ   (CeTZ/cetz-plot/fletcher builders)
├── figs/               # cropped source screenshots
├── coverage.md         # source page -> section ledger
├── sections/NN-*.typ   # one file per Part (split at ~700 lines)
├── scratchpad/verify/  # python recompute scripts (not shipped)
├── out.pdf             # compiled
└── README.md           # package list, build command, font note

Copy references/template.typ and references/diagrams.typ (proven on Typst 0.15.x), adapt palette, header text and fonts, then run bash <skill>/scripts/sync-versions.sh <proj>. Write main.typ from references/main-skeleton.typ.

5. Verify numerics

For each source with worked problems, write scratchpad/verify/<part>.py that recomputes every example (perceptron epochs, gradient steps, matrix products, recall vectors, whatever the domain needs). Run it. Use its output as the source of truth for the prose. references/verify-example.py is a worked sample (neural-network numerics) to pattern-match against.

5b. Source screenshots

Wherever a source slide diagram, table or equation image explains better than a redraw, screenshot it: render the page (pdftoppm), Read the PNG to pick the crop box, crop tight (no slide chrome), save in figs/, and embed as #figure(image("figs/..."), caption: [...#sref[Lecture N]]). Redraw only if the source image is blurry or cluttered. Commands in references/typst-cookbook.md > Screenshots. Ask about screenshots in the grill.

6. Build the sections

Format contract (hard). Notes are labelled blocks, never walls of text. Read references/topic-example.typ and copy its shape for every topic.

  • Headings: H2 per topic, H3 per subtopic (why / definition / types / steps / formula / comparison / example / pitfalls), H4 for cases. At most ~150 words under any heading.
  • Default block per piece of information: terms = definition box; properties/rules/conditions = bullets (one idea each, <= 2 lines); procedures = numbered steps; contrasts, states, parameters, costs = tables; key formulas = keyform (every symbol explained); structure/flow/timing = diagram or source screenshot; numbers = worked; traps = pitfall/tip.
  • No paragraph walls: a paragraph is <= 3 lines and rare. If a paragraph lists things, make it bullets; if it compares things, make it a table.
  • Source check: where the source has an error, gap or inconsistency, use sourcecheck[...] naming only the unit/lecture, and list each in the end-matter register (Where / Issue / Used). Never silently fix.
  • Notation: if the notes’ symbols differ from the source’s, add one notemap(...) row in the front matter or first use.
  • Callout discipline: intuition, pitfall, watch, tip as needed; trick (mnemonics) and check only where one really exists, never every topic. Key formulas get keyform(..., legend: ((sym, meaning), ...)).
  • Chapter cover (balanced/rich, detailed/exam): open each chapter with chapter-cover(colour, title, topics:, learn:, hero:) and a distinct colour per chapter; the hero is a real figure (see references/rich-visuals.md).
  • Source tag: one sref per topic (in the definition or a caption), light form only: unit or lecture name, no slide or page numbers, e.g. #sref[Unit I]. Never per sentence.
  • Spine per topic (skip only what truly does not exist): intuition (1-3 lines) > definition/formula boxes > method steps > worked examples (every source problem + 2 extra) > pitfalls > practice (3-5).
  • Coverage: every source page is mapped in coverage.md (see Gates below). Organize sections by concept, not source order. Coverage lives in the ledger, never in the prose.

Gates, both must pass before delivery: python3 <skill>/scripts/coverage-check.py <proj> (keep coverage.md: one row per source page: | file.pdf | page | topic | section file or skip: reason |) and python3 <skill>/scripts/structure-check.py <proj> (headings every ~150 words, paragraphs short, boxes, list/table items and figures per 1000 words). On failure, restructure the section; never loosen the thresholds. Writer agents run structure-check.py on their own file before reporting.

End-matter Part: master formula sheet (showybox cards), comparison matrices (tablem), pitfall index (numbered, body callouts point here), symbol glossary, the source-check register (Where / Issue / Used, from every sourcecheck), a “how to attack a problem” table + fletcher decision flowchart, and the practice answer key (final answers only, keyed by topic).

Wire the end-matter with xref / backlink (hard rule 6): every answer-key entry links to its question and back, every pitfall-index entry links to its body callout and back, every formula card links to where it was first derived and back. Any forward mention in the section prose gets the same treatment.

Compile after each section: typst compile main.typ out.pdf. First compile downloads the packages (needs network once). Fix every error and warning before moving on. Read references/typst-cookbook.md for the syntax traps.

7. Review pass — density and gaps

First check the build against notes-config.md: every requested block and matter present, nothing excluded present, each remark visibly honoured. Fix gaps.

Run both gates first. Then render a sweep of pages to PNG and actually look. Any page that reads as a block of text, or lacks visible separation (headings, boxes, tables, spacing), is a defect: restructure it. typst compile --pages A-B main.typ "/tmp/rev/p-{p}.png" --ppi 90

  • No page should be more than ~20% empty at the bottom from a block that jumped whole. If chapters are forcing page breaks, remove the pagebreak from the level-1 heading show rule (the template ships without it).
  • Tighten par(leading:, spacing:) and showybox inset / spacing if the layout feels loose; loosen if it is cramped.
  • Every #figure renders, nothing clipped, body never scrolls horizontally.
  • Margins symmetric, text column fills the page (no wide empty side margin); screenshots sharp and cropped tight.
  • Every xref mention is visibly linked and lands on the right target; every target shows its backlink ↩ marker(s) and each returns to a distinct spot. A dangling #link(<label>) warns at compile — rule 3 already fails the build.
  • Print one page in greyscale mentally: callouts still tell apart by icon+label.

8. Deliver

SendUserFile the compiled PDF. Report: page count, clean-compile confirmation, the section list, and where the .typ sources + verify scripts live. Write the README (package table with pinned versions, typst compile command, font note: needs New Computer Modern / New Computer Modern Math).

Diagrams

Gallery first. references/gallery/ holds compile-verified demo-* functions (exact imports, versions, gotchas in comments). Read the relevant file, copy the demo, adapt. Do not guess a package API when a demo exists.

File Covers
gallery/ml-quantum-math.typ quill circuits, Bloch sphere (czbloch/tybloch), lilaq plots/heatmap/contour, cetz-plot, Venn, equation annotation (mannot, equate), CNN (neural-netz), pipelines (neural-viz), confusion matrix, MLP/transformer/backprop (fletcher), Graphviz DAG, probability trees
gallery/systems-hw.typ bytefield (packet/register), blockcell, network topology, CPU datapath (circuiteria), circuits (zap), timing (digidraw), K-map, truth table, DFA (finite), stack/heap, 5-stage pipeline, cache lookup, memory hierarchy, page walk, MPI send/recv + allreduce, process states, TCP handshake
gallery/sde-algo-layout.typ sequence (chronos), ER (pintorita), UML (mastermind), Gantt (timeliney), trees (tdtr/arborly), inference/Fitch proofs, pseudocode (lovelace/algorithmic), code with highlights (codly), margin notes (marginalia), text wrap, sub-figures, hand-drawn look, SDLC models, git graph, memory pictures, BFS, call stack, big-O plot

If the concept is not in the gallery, search the package catalog (cookbook), build a minimal demo in a scratch file, and only then use it. Add a new verified demo to the gallery when it works and is reusable.

Fallback order when no demo fits:

(1) a domain package from the catalog (quill, czbloch, finite, chronos, timeliney, circuiteria, bytefield, neural-netz, …); (2) fletcher for node-arrow structure; (3) cetz + cetz-plot or lilaq for geometry and plots; (4) a cropped source screenshot. Use colour sparingly and consistently, label directly on the figure, caption every figure with what to notice, not what it is.

Packages: always latest, never pinned by hand

Run bash <skill>/scripts/sync-versions.sh <proj> right after scaffolding and again before delivery. It rewrites every @preview/<pkg>:<ver> import to the newest registry version. Then compile. If a major bump breaks the build, read that package’s README in ~/.cache/typst/packages/preview/<pkg>/<ver>/ and fix the call (do not pin back unless the fix takes more than 2 attempts; then note the pin in README.md). The shipped templates were last verified on: codly 2.x (new codly.* API), cetz 0.5.x, Typst 0.15.

Baseline (swap or add per recon): cetz, cetz-plot (or lilaq), fletcher, great-theorems + rich-counters, showybox (key-formula cards only), codly + codly-languages, physica, hydra, tablem.

Files in this skill

  • references/typst-cookbook.md — read first. Versions, exact import/setup lines, and the Typst syntax-trap list.
  • references/template.typ — proven styles + notes-conf + all helpers (intuition, tip, watch, pitfall, remember, derivation, definition, theorem, property, lrule, worked, practice, algo, keyform, sref, xref, backlink, part, plus trick, check, sourcecheck, pill, notemap, chapter-cover). Copy verbatim.
  • references/notes-config.md — the recipe + binding remarks template (wizard output).
  • references/rich-visuals.md — 3D/hero figures via headless chromium (Three.js, canvas, SVG), embed as PNG.
  • references/html-kit/ + scripts/html-to-pdf.sh — HTML to PDF track (same palette and callout names; KaTeX for math).
  • references/diagrams.typ — proven CeTZ/cetz-plot/fletcher builders (layered-net, neuron, act-plot, decision-boundary, signal-flow-bpn, gaussian-kernel, delay-line, pattern-grid, nm). Copy verbatim; add domain-specific builders alongside.
  • references/topic-example.typ — one correctly structured topic; copy its shape.
  • scripts/coverage-check.py, scripts/structure-check.py — delivery gates.
  • references/main-skeleton.typ — starter main.typ (title, how-to-use, TOC, part dividers, includes).
  • references/verify-example.py — sample numeric-verification script.
  • scripts/extract.sh — lit parse batch wrapper.
  • references/gallery/*.typ — verified diagram demos (see Diagrams).
  • scripts/sync-versions.sh — bump all @preview imports to latest.
